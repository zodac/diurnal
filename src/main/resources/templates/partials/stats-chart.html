{! The Stats page's frequency graph — the body of the graph modal, re-rendered server-side on every period flip, window step, and change to the set of charted actions (see StatsInternalResource.chart). Rendering the bars here rather than shipping figures to a client-side charting library keeps every caption, value and hover string on the same code path as the rest of the page's figures, so the modal needs no charting code at all — stats.js only fetches this fragment and swaps it in. Up to FrequencyCharts.MAX_SERIES actions are charted together, their bars grouped within each column and all scaled against ONE peak so they are directly comparable. Every slot of the window gets a column, including the empty ones, so the axis stays evenly spaced and a blank run reads as a visible trough. Bar heights and tooltip anchors are pre-computed (FrequencyCharts); the hover wording itself is composed by partials/frequency-slot-tooltip, since it needs a translated "N times" per bar — there is no other branching left in here beyond the empty-window case, the two disabled navigation buttons and whether the compare picker is offered. Params: chart — the FrequencyChart to draw (required) candidates — the actions the compare picker may offer (required; may be empty) !} {! The shown period/window/comparisons are echoed onto the wrapper under DISTINCT attribute names from the buttons' own data-chart-period/data-chart-at, so stats.js's delegated `closest(...)` lookups can never mistake the wrapper itself for a control the user clicked. !}
