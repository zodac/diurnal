{! Shared labelled input for form-based modals (login, register — and any future ones). Routing every field through this one partial keeps the markup identical, so the shared client-side validator in layout.html (forms marked `data-validate`) treats them all the same and surfaces blank/invalid fields as in-page banners instead of native browser pop-ups. The `data-field-label` it stamps is the name the validator lists for a blank required field. Strict rendering throws on a missing key inside `{#if …}`, so the `#if`-tested attributes must ALWAYS be supplied by the caller (pass "" / false to omit). Params: id, name, label — text (required) required — boolean, whether the field is mandatory (required) autocomplete — autocomplete token, or "" for none (required) maxLength — the field's bound in CODE POINTS, or "" for none (required). Emitted as `data-max-length`, never as the HTML `maxlength` attribute: that one counts UTF-16 units, so it silently halves the allowed length for astral text (an emoji in a display name). The server owns the bound; this is the DECLARED value, for anything that wants to read it. type — input type (optional, default "text") value — pre-filled value (optional, default "") !}
gives. Resolves to ltr for an empty field, and for a password field by definition. !} dir="auto" value="{value ?: ''}" data-field-label="{label}" class="form-input w-full">
