{! Live password-requirements popover. Reveals while the associated password INPUT (whose id is passed as `for`) is focused, and each requirement turns green when met / red when unmet as the user types. The rows are generated from TextFieldExtensions.constraints(TextFields.PASSWORD), read straight off the injected catalogue bean so the partial needs nothing from its including page. The live red/green evaluation is the single `[data-pw-tooltip]` handler in layout.html — whose check tokens (minLength / maxLength) mirror TextConstraint.type. So the tooltip can never drift from the server-enforced rules: change the bounds in the TextFields catalogue and the rows follow, on both the registration and settings pages, automatically. Place inside a `relative` wrapper at the call site (the nearest positioned ancestor it anchors to). Only the NEW-password field opts in — never the current-password or confirm fields. Params: for — id of the password this popover describes (required) differsFrom — id of an input holding a password the value must NOT equal (optional; the change-password flow points this at the stashed current password, so "must be a new password" is a visible, live-checked requirement like the length ones). Registration has no such field and simply omits it. !} {#let differsFromId=differsFrom.or('')}

  • ✗ {c.label}
    • {/for} {#if differsFromId != ''}
  • ✗ Different from your current password

{/let}
