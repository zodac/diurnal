{! Translated text for a rejected free-text submission (net.zodac.diurnal.text.TextOutcome.Failure), rendered via a nested Template.render() call from the web surface of whichever *Result carries it (ActionResult.InvalidName, NoteResult.Invalid, PasswordChangeResult.InvalidNewPassword). The API's own English text is unaffected - it still calls TextOutcomeExtensions.message(failure) directly, by design (see that method's own Javadoc). One whole, atomic sentence per (field, failure shape) - never a `{fieldLabel} {requirement}` substitution, even though a substitution would still let a translator reorder words: the rule wording ("cannot contain...") is a dependent clause written to follow a specific subject, and subject-verb/article agreement (a real concern in many languages) cannot be fixed by reordering a shared template alone. See AppMessages' own "Text-validation pipeline rejections" section for the full reasoning.
